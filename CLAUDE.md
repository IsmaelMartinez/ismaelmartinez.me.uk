# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Start development server
npm run build        # Build for production (output in ./dist)
npm run preview      # Preview production build
npm run lint         # ESLint across the repo
npm run typecheck    # Astro + TypeScript check
npm test             # Run Vitest suite (build tests require ./dist to exist)
```

## Architecture

This is a multilingual Astro static site with three supported locales: English (en), Spanish (es), and Catalan (cat). The site uses file-based routing with locale prefixes (all pages live under `/en/`, `/es/`, `/cat/`).

### Internationalisation

The i18n system centres on `src/i18n/translations.ts`, which exports the `useTranslations(lang)` function used throughout components. Every UI string is keyed in this file across all three locales. The `getLangFromUrl()` and `getLocalizedPath()` helpers handle routing between language versions.

Pages are defined once under `src/pages/[lang]/…` as dynamic routes that use `getStaticPaths()` to emit `/en/`, `/es/`, and `/cat/` variants (see `docs/plans/2026-02-15-phase4-security-maintainability-design.md` for the deduplication rationale). The root `src/pages/index.astro` redirects to the default locale (`/en/`), and `src/pages/404.astro` is the shared 404.

### Content

Static data (projects, links, health, person) lives in TypeScript files under `src/data/` with inline translations per object. Articles use Astro Content Collections in `src/content/articles/{locale}/` with MDX format. The schema is defined in `src/content.config.ts` (Astro 6's top-level content config location).

Articles follow POSSE (Publish Own Site, Syndicate Elsewhere) strategy per ADR 001 in `docs/adr/`. Frontmatter includes `originalUrl` and `originalPlatform` to link back to syndicated copies on Medium/Dev.to.

### Arcade games

Arcade pages live under `src/pages/[lang]/fun/`. Newer games (Tank Duel, Pixel Park (parked off the floor, see below), Microcity, Line Hold, Cascade) split pure game logic into DOM-free TypeScript modules under `src/games/<game>/` (unit-tested in `tests/games/`) with a single `init<Game>()` entry the page calls; shared utilities (fixed-timestep loop, hi-DPI canvas setup (`canvas.ts` — DPR-scaled backing store with a logical-coordinate contract; pointer math must use its `toLogical()`, never `canvas.width`), top-10 high-score tables with arcade initials entry (`highscores.ts` + `scoreboard.ts` + `src/components/HighScoreTable.astro`), where each cabinet's panel shows one board, the global one every visitor shares (a Vercel Function at `api/scores.ts` over one Vercel Blob JSON file per game, with the client seam in `src/games/engine/globalScores.ts`; the decision to run this on the Vercel deployment the site already has, why an earlier Cloudflare recommendation was reversed, and why the per-device board that used to sit beside it under a pair of tabs was removed on 2026-07-29, are all recorded in `docs/adr/002-global-arcade-high-scores.md`), grid helpers, shared BFS pathfinding (`pathfind.ts` — a walkability predicate over the flat grid; Pixel Park, Syndicate, and Line Hold all route through it), isometric renderer) live in `src/games/engine/`. Three engine modules are the *required* channel for game feedback — new games must not re-paste them: `toast.ts` (`createToaster` — DOM toast stack, cap 3, timed auto-remove, swap-safe timers), `effects.ts` (`createEffects` — canvas particle bursts + text floaters; per-game constants go in as construction options, bespoke spawn math hands finished particles to `emit()`, and a copy that genuinely can't fit the options stays local with a comment naming the divergence — today only Critter Rescue's), and the scoreboard's run-record API (`beginRun()` at run start, `bank(score)` on every gain → `{ best, newRecord }` for the HUD readout and the one-time record toast, `best()` for init-time HUD seeding). Render loops must not rebuild static full-canvas content (starfields, checkerboards, vignettes) per frame: bake it with `createStaticLayer` in `canvas.ts`, rebuilt via `setupHiDpiCanvas`'s `onApply` (its JSDoc carries the device-pixel alignment contract). The one exception is a full-canvas gradient fill that doubles as the frame clear (the sims' skies), which keeps a hoisted `CanvasGradient` instead. The iso cabinets' shared drawing idioms also live in the engine and are the required channel — don't re-derive them per game: `blockFaceCorners`/`blockSeamPath` in `iso.ts` (inset footprint corners + the W→S→E course line across a block's visible faces), `faceBandPath` (the interpolate-along-projected-edge quad behind shopfront glass, office strips, counter bands, and two-edge awning canvas; path-append so callers keep their own fill batching), and `blink` beside `hash01` in `canvas.ts` (the 1.5 Hz rooftop-beacon cadence, phase-offset by tile index). Geometry that is a pure function of slow-changing state gets cached, not recomputed per frame: Microcity memoizes per-tile hashed variety (hash rolls + derived colour strings) per `type:level` key — from the 2026-07-20 consolidation round (`docs/plans/2026-07-20-arcade-consolidation-2-drawing-idioms.md`). (Pixel Park once baked per-track-tile rail geometry into a `railCache` here too; that cache retired with the lay-your-own-track coaster — see Round 12.) Render refactors that must not change output are verified byte-identically with `scripts/screenshot-games.js` (deterministic seeded-PRNG + stepped-rAF captures; not in CI — see its header for the ad-hoc setup). Its `PARKED` list keeps the parked cabinets' sections (Pixel Park, Syndicate) out of the default run, since their pages are unrouted and a 404 would abort the whole capture; naming one explicitly still runs it, once the page is un-parked. Static labels render server-side via `useTranslations`; runtime-composed strings pass through `data-t-*` attributes on the game root. New games register cabinet art in `src/data/arcadeCabinets.ts` and a link in the unlock chain (below). Since 2026-08-11 the floor is themed **under construction** (caution-tape accents and a trilingual "pardon our dust" sign, `fun.arcade.wip.sign`), and Round 6's two labelled Featured/Back-catalogue shelves are retired — the `fun.arcade.shelf.*` i18n keys went with them. In their place stands a **progressive unlock chain**, a walk through gaming history ordered by the era of the classic each cabinet homages (tanks 1974 → snake 1976 → cascade 1985 → city 1989 → lemmings 1991 → towerdefense 2007; each live cabinet wears an `EST. <year>` plaque, numerals only so no i18n) whose logic lives in `src/games/engine/progress.ts`: the `UNLOCK_CHAIN` constant, `completedGames()` reading `arcade-done-<gameId>` localStorage flags (seeded from any `arcade-best-<gameId>` > 0, so returning players keep their floor), `markDone(gameId, score)` which records only a score above zero — finishing with nothing on the board reveals nothing — and the pure `visibleCabinets(chain, doneSet)` — unit-tested in `tests/games/progress.test.ts`. Three rules in that module are load-bearing. A cabinet that scores under more than one `gameId` is normalised through `CHAIN_ALIASES` before it touches storage or the seed (today only Cascade's `cascade-countdown`, whose runs would otherwise never power the `cascade` link). Unusable localStorage **fails open**: `completedGames()` returns the whole chain, because progress could never be recorded on such a device and a gated floor would strand the player behind a hint promising an unlock that can never land. And the `arcade-done-*` family is deliberately kept even though it looks derivable from `arcade-best-*`: Tank Duel marks done on runs that never bank a best (see below), so done ≠ best and collapsing the two would re-stall the chain. Tank Duel is always on; scoring on the newest unlocked cabinet powers the next, which renders as the floor's single shrouded/tarped "?" silhouette with the parameterised `fun.arcade.locked.hint` naming only its predecessor. **The next cabinet is a mystery**, and the invariant that protects it is precise: no PLAINTEXT hidden-cabinet identity (marquee name, icon, colour, tagline) in the built HTML or in the floor's JS bundle. The static HTML carries only the always-on first cabinet and the anonymous shroud; every chain cabinet's display data is composed **server-side** in the floor page's frontmatter through `useTranslations` (title, icon, colour, localized tagline/genre/players, the pre-formatted `EST. <year>` plaque string, an `isNew` flag for the localized `fun.arcade.new` ribbon, and the shroud hint naming that cabinet) and shipped as a base64-of-JSON island (`<script type="application/json" data-floor-data>`), which the client script decodes to clone the first cabinet's DOM (the clone keeps Astro's scoped-style attributes; a ribbon it creates is given the same `data-astro-cid-*` marker) and patch. **The floor's client script must not import `src/data/arcadeCabinets.ts` or the translations module**: the first would ship every hidden cabinet's art in plaintext, the second would bundle the whole three-locale dictionary to render five taglines, against the server-side-labels rule above. The base64 is spoiler-guarding, not security: the game pages stay public, sitemapped routes, chain ids (which are also route slugs and localStorage key names) do remain in the bundle, and the encoding is trivially reversible by anyone determined — accepted, because it only has to keep casual view-source and asset-grep clean. `visibleCabinets` measures progress from the deepest finished cabinet, so a done set with gaps never shrinks a floor already reached. Because the floor is client-rendered, the five cabinets past the first have **no static HTML link**: the crawl trade-off is accepted (every game page is still in the sitemap), and an i18n'd `<noscript>` line (`fun.arcade.noscript`) tells a JS-less visitor the arcade needs JavaScript to reveal its cabinets. `markDone` is wired in exactly two places: `scoreboard.ts`'s `commit()`, which every scored run already passes through (regression in `tests/games/scoreboard-dom.test.ts`), and Tank Duel's match end, which calls it directly on a completed **two-player** match and only there — the chain's first cabinet would otherwise stall for every player who only ever plays two-player, since a 2P match never reaches the board. Vs the CPU it is not called directly at all: every finished CPU match submits, so `commit()` already marks the cabinet, which puts tanks on the same rule as every other cabinet — **score anything and the next one appears**, not "win a round" (the narrower `wins[0] > 0` gate this once carried had become dead code once submission stopped depending on winning). That leaderboard gate is `submitsToBoard(mode)`, vs-CPU and nothing else, and is load-bearing in the direction it points: it must not be widened to two-player (see the scoring conventions below). Only the floor is gated: direct URLs to still-shrouded games always work. Scoring conventions across the cabinets: there is **one board**, the global one every visitor shares, served by a Vercel Function at `api/scores.ts` backed by Vercel Blob (client seam `src/games/engine/globalScores.ts`, submission wired into `scoreboard.ts`'s `commit()`; the rejected alternatives and the Cloudflare-to-Vercel reversal behind this choice are in `docs/adr/002-global-arcade-high-scores.md`, whose "Corrections from production" section records what running the write path for real disproved: `put` has no conditional *create*, so an absent read is never taken at face value; it also records that the CDN does cache the read on plain `max-age`, measured against the deployed endpoint after a review claimed otherwise, so `s-maxage` is belt-and-braces rather than load-bearing). What `highscores.ts` still keeps on the device is only the last-used initials and a **personal best number per game** (`loadBest`/`saveBest`, key `arcade-best-<gameId>`, migrating once from the retired `arcade-hs-*` tables and then from the pre-table single-number keys; a cabinet whose scoring scale changes gets a version suffix through `BEST_KEY_VERSION` instead — today only `tanks`, at `-v2`, whose old key held a 100–400 match margin that the ledger score outgrew by an order of magnitude, and a rescaled game reads its versioned key alone since every older source predates the change); that number is what `best()`, the HUD readouts, the record toast, and the arcade floor's attract screens read. Four rules here are load-bearing and easy to undo by accident, so do not re-gate them. **Every finished run with a score above zero is submitted** — `qualifies()` decides only whether the player is interrupted for initials, never whether the run reaches the board, because gating the submission on a private table is exactly the bug that left eight of the nine live boards holding a single entry each (regression pinned in `tests/games/scoreboard-dom.test.ts`). The board is **refetched at panel init and again at every run end**, since a player has no refresh button and a once-only load froze the shared board for a whole session. And both a fetch's reply and a submission's own reply are ordered by the single `worldGen` generation that only a submission bumps, so an overtaken or out-of-order answer stands down instead of putting an older board back on screen. Finally, **a submission that does not land says so** in the panel note (`fun.arcade.scoreNotSaved`), because with no device table behind it a failed write loses the run outright; the notice is gated on `canSubmit()` so local dev and previews, which read the board but never write to it, stay quiet rather than crying wolf. `commit()` records the finished run through the run record's `bank()` rather than writing `saveBest` behind its back (so `best()` and storage cannot disagree mid-session), and fires `onSave` once per committed run whatever became of it, with rank 0 when it did not chart or did not land. Server-side, `top` is the **persisted all-time top ten**, merged per write by `mergeTop` rather than re-derived from a rolling history (which silently expired records once a board passed the history cap), and one pruned `recent` array carries replay dedupe plus both rate limits. Beyond that: games whose runs can be long (Microcity, Pixel Park, Syndicate, Line Hold, Cascade, Tank Duel) bank the run's best as it grows — `bank(score)` stashes automatically — so a closed tab never loses a record; every point gain is announced on screen the moment it lands (canvas floaters/score popups via `createEffects`); the number a finished run submits is shown to the player rather than computed silently (e.g. Tank Duel's match score, Critter Rescue's bonus breakdown); and beating the personal best mid-run earns a one-time toast driven by `bank()`'s `newRecord` flag; Critter Rescue is also long-run but banks on level-clear only, and never calls `beginRun()`, which leaves the celebration unarmed so it fires no mid-run record toast. `bank()` is the **only** write path to the persisted best: the `Scoreboard` interface deliberately exposes no second verb for it, so the number in memory and the one on disk cannot drift apart.

Tank Duel was the cabinet that broke every one of those conventions at once, and was rebuilt to them on 2026-08-12. A single `playerWonMatch` boolean used to decide three separate things — whether the score was visible, whether the panel opened, and whether the run was offered — so a player who did not beat the CPU saw no number at any stage of a match; and the number itself, `physics.ts`'s retired `matchScore` (round margin × 100 + surviving armour), only existed at match end and was negative for most of a match's life. The rules now live in `src/games/tanks/scoring.ts` and are pure and unit-tested (`tests/games/tanks.test.ts`): `createScoreLedger()` pays **1 point per hp of damage landed on the opponent** as it lands, **25 for detonating a shell on the enemy hull**, **250 for taking a round**, and folds **surviving armour in once at match end**. Self-damage and fall damage (a drop has no shooter) pay nothing, and **nothing is ever subtracted** — the ledger's private `add` drops any non-positive award rather than banking it, because a negative running total was the original bug in miniature. Both modes score identically and both call `beginRun()`; the awards fire gold `+NN` floaters through the shared `createEffects` beside the red damage popups, and drive SCORE and BEST readouts plus the record toast through the shared `createToaster`. Only **submission** differs, through the pure `submitsToBoard(mode)`, which is `mode === 'cpu'` and nothing else. Two-player never reaches the world board and never banks against the personal best that feeds the floor's attract screens, because one person driving both tanks can farm any total they like; a 2P match ends instead on a local-only overlay showing both totals side by side. The gate is deliberately *not* also conditioned on winning — a lost match that earned 900 points is a finished run worth 900, and `qualifies()` decides only whether to interrupt for initials. The bespoke `tanks-victories` counter is retired with the old scoring (its `LEGACY_KEYS` exclusion note in `highscores.ts` still stands); its header slot now carries SCORE, beside a BEST that swaps out for the second player's score in two-player.

### Layouts and Components

`src/layouts/Layout.astro` is the base layout with navigation, language switcher, and footer. `src/layouts/ArticleLayout.astro` handles article pages. Components in `src/components/` are shared across locales.

Top-level nav is deliberately four items — Home, About, Projects, Writing (owner-approved simplification, 2026-08). `src/pages/[lang]/connect.astro` was removed: its grouped link lists (the `LinkCard`-rendered `read`/`connect` groups from `src/data/links.ts`, including the RSS `feedLink`) now live inside `about.astro` under an `id="connect"` section, so every CTA that used to point at `/connect` (the Hero button, the footer link, the article "discuss" link) now targets `/about#connect` directly. `astro.config.mjs`'s `redirects` sends the three old `/{lang}/connect` paths to `/{lang}/about#connect` for anyone with a stale bookmark or inbound link. `/health` stays fully live and linked (a "Project health" link sits next to the `PortfolioHealthBadge` on `projects.astro`) but is no longer in the nav bar.

### Testing & CI

Vitest tests live under `tests/` (unit tests for i18n and reading-time, the arcade game-logic suites under `tests/games/`, plus `tests/build/output.test.ts` which reads files from `./dist` and is skipped unless a build has been produced). Vitest runs in the node environment by default; jsdom is installed and opted into per file (`/** @vitest-environment jsdom */`), which is how `tests/games/scoreboard-dom.test.ts` covers `scoreboard.ts`'s DOM wiring — other DOM-wired changes are still verified in a browser against `npm run dev`. The link checker in `scripts/check-links.js` walks built HTML in `./dist/` and verifies internal hrefs resolve to real files. CI (`.github/workflows/ci.yml`) runs lint, typecheck, build, tests, and link check on pushes to `main`/`develop` and PRs to `main`.

### Deployment

The deploy workflow (`.github/workflows/gh-pages.yml`) runs after a successful CI on `main` (and on a six-hourly cron) to build and publish to GitHub Pages. Output goes to `./dist`. The Vercel deployment (configured by `vercel.json`) mirrors the site and is the production host for the global-scores Function at `api/scores.ts` (see ADR 002).
