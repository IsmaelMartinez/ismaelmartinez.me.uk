## Architecture

This is a multilingual Astro static site with three supported locales: English (en), Spanish (es), and Catalan (cat). The site uses file-based routing with locale prefixes (all pages live under `/en/`, `/es/`, `/cat/`).

### Internationalisation

The i18n system centres on `src/i18n/translations.ts`, which exports the `useTranslations(lang)` function used throughout components. Every UI string is keyed in this file across all three locales. The `getLangFromUrl()` and `getLocalizedPath()` helpers handle routing between language versions.

Pages are defined once under `src/pages/[lang]/…` as dynamic routes that use `getStaticPaths()` to emit `/en/`, `/es/`, and `/cat/` variants (see `docs/plans/2026-02-15-phase4-security-maintainability-design.md` for the deduplication rationale). The root `src/pages/index.astro` redirects to the default locale (`/en/`), and `src/pages/404.astro` is the shared 404.

### Content

Static data (projects, links, health, person) lives in TypeScript files under `src/data/` with inline translations per object. Articles use Astro Content Collections in `src/content/articles/{locale}/` with MDX format. The schema is defined in `src/content.config.ts` (Astro 6's top-level content config location).

Articles follow POSSE (Publish Own Site, Syndicate Elsewhere) strategy per ADR 001 in `docs/adr/`. Frontmatter includes `originalUrl` and `originalPlatform` to link back to syndicated copies on Medium/Dev.to.

### Arcade games

Arcade pages live under `src/pages/[lang]/fun/`. Newer games (Tank Duel, Pixel Park (parked off the floor, see below), Microcity, Line Hold, Cascade) split pure game logic into DOM-free TypeScript modules under `src/games/<game>/` (unit-tested in `tests/games/`) with a single `init<Game>()` entry the page calls; shared utilities (fixed-timestep loop, hi-DPI canvas setup (`canvas.ts` — DPR-scaled backing store with a logical-coordinate contract; pointer math must use its `toLogical()`, never `canvas.width`), top-10 high-score tables with arcade initials entry (`highscores.ts` + `scoreboard.ts` + `src/components/HighScoreTable.astro`), where each cabinet's panel shows one board, the global one every visitor shares (a Vercel Function at `api/scores.ts` over one Vercel Blob JSON file per game, with the client seam in `src/games/engine/globalScores.ts`; the decision to run this on the Vercel deployment the site already has, why an earlier Cloudflare recommendation was reversed, and why the per-device board that used to sit beside it under a pair of tabs was removed on 2026-07-29, are all recorded in `docs/adr/002-global-arcade-high-scores.md`), grid helpers, shared BFS pathfinding (`pathfind.ts` — a walkability predicate over the flat grid; Pixel Park, Syndicate, and Line Hold all route through it), isometric renderer) live in `src/games/engine/`. Three engine modules are the *required* channel for game feedback — new games must not re-paste them: `toast.ts` (`createToaster` — DOM toast stack, cap 3, timed auto-remove, swap-safe timers; its markup and presentation are the matching required channel, `src/components/ToastArea.astro`, which a cabinet page drops in instead of hand-rolling the `#toast-area` div and its CSS — that block had been pasted into six pages and drifted, and the component's own note records why it sets no `z-index` and why long toasts wrap), `effects.ts` (`createEffects` — canvas particle bursts + text floaters; per-game constants go in as construction options, bespoke spawn math hands finished particles to `emit()`, and a copy that genuinely can't fit the options stays local with a comment naming the divergence — today only Critter Rescue's), and the scoreboard's run-record API (`beginRun()` at run start, `bank(score)` on every gain → `{ best, newRecord }` for the HUD readout and the one-time record toast, `best()` for init-time HUD seeding). Render loops must not rebuild static full-canvas content (starfields, checkerboards, vignettes) per frame: bake it with `createStaticLayer` in `canvas.ts`, rebuilt via `setupHiDpiCanvas`'s `onApply` (its JSDoc carries the device-pixel alignment contract). The one exception is a full-canvas gradient fill that doubles as the frame clear (the sims' skies), which keeps a hoisted `CanvasGradient` instead. The iso cabinets' shared drawing idioms also live in the engine and are the required channel — don't re-derive them per game: `blockFaceCorners`/`blockSeamPath` in `iso.ts` (inset footprint corners + the W→S→E course line across a block's visible faces), `faceBandPath` (the interpolate-along-projected-edge quad behind shopfront glass, office strips, counter bands, and two-edge awning canvas; path-append so callers keep their own fill batching), and `blink` beside `hash01` in `canvas.ts` (the 1.5 Hz rooftop-beacon cadence, phase-offset by tile index). Geometry that is a pure function of slow-changing state gets cached, not recomputed per frame: Microcity memoizes per-tile hashed variety (hash rolls + derived colour strings) per `type:level` key — from the 2026-07-20 consolidation round (`docs/plans/2026-07-20-arcade-consolidation-2-drawing-idioms.md`). (Pixel Park once baked per-track-tile rail geometry into a `railCache` here too; that cache retired with the lay-your-own-track coaster — see Round 12.) Render refactors that must not change output are verified byte-identically with `scripts/screenshot-games.js` (deterministic seeded-PRNG + stepped-rAF captures; not in CI — see its header for the ad-hoc setup). Its `PARKED` list keeps the parked cabinets' sections (Pixel Park, Syndicate) out of the default run, since their pages are unrouted and a 404 would abort the whole capture; naming one explicitly still runs it, once the page is un-parked. Three rules in that module are load-bearing. A cabinet that scores under more than one `gameId` is normalised through `CHAIN_ALIASES` before it touches storage or the seed (today only Cascade's `cascade-countdown`, whose runs would otherwise never power the `cascade` link). Unusable localStorage **fails open**: `completedGames()` returns the whole chain, because progress could never be recorded on such a device and a gated floor would strand the player behind a hint promising an unlock that can never land. And the `arcade-done-*` family is deliberately kept even though it looks derivable from `arcade-best-*`: Tank Duel marks done on runs that never bank a best (see below), so done ≠ best and collapsing the two would re-stall the chain. Tank Duel is always on; scoring on the newest unlocked cabinet powers the next, which renders as the floor's single shrouded/tarped "?" silhouette with the parameterised `fun.arcade.locked.hint` naming only its predecessor. **The next cabinet is a mystery**, and the invariant that protects it is precise: no PLAINTEXT hidden-cabinet identity (marquee name, icon, colour, tagline) in the built HTML or in the floor's JS bundle. The static HTML carries only the always-on first cabinet and the anonymous shroud; every chain cabinet's display data is composed **server-side** in the floor page's frontmatter through `useTranslations` (title, icon, colour, localized tagline/genre/players, the pre-formatted `EST. <year>` plaque string, an `isNew` flag for the localized `fun.arcade.new` ribbon, and the shroud hint naming that cabinet) and shipped as a base64-of-JSON island (`<script type="application/json" data-floor-data>`), which the client script decodes to clone the first cabinet's DOM (the clone keeps Astro's scoped-style attributes; a ribbon it creates is given the same `data-astro-cid-*` marker) and patch. **The floor's client script must not import `src/data/arcadeCabinets.ts` or the translations module**: the first would ship every hidden cabinet's art in plaintext, the second would bundle the whole three-locale dictionary to render five taglines, against the server-side-labels rule above. The base64 is spoiler-guarding, not security: the game pages stay public, sitemapped routes, chain ids (which are also route slugs and localStorage key names) do remain in the bundle, and the encoding is trivially reversible by anyone determined — accepted, because it only has to keep casual view-source and asset-grep clean. `visibleCabinets` measures progress from the deepest finished cabinet, so a done set with gaps never shrinks a floor already reached. Because the floor is client-rendered, the five cabinets past the first have **no static HTML link**: the crawl trade-off is accepted (every game page is still in the sitemap), and an i18n'd `<noscript>` line (`fun.arcade.noscript`) tells a JS-less visitor the arcade needs JavaScript to reveal its cabinets. `markDone` is wired in exactly two places: `scoreboard.ts`'s `commit()`, which every scored run already passes through (regression in `tests/games/scoreboard-dom.test.ts`), and Tank Duel's match end, which calls it directly on a completed **two-player** match and only there — the chain's first cabinet would otherwise stall for every player who only ever plays two-player, since a 2P match never reaches the board. Vs the CPU it is not called directly at all: every finished CPU match submits, so `commit()` already marks the cabinet, which puts tanks on the same rule as every other cabinet — **score anything and the next one appears**, not "win a round" (the narrower `wins[0] > 0` gate this once carried had become dead code once submission stopped depending on winning). That last clause is only true because the canvas box is sized in **device** pixels by `game.ts` rather than by CSS: `render.ts`'s pure `integerScale(availW, availH, dpr)` picks the largest whole multiple of 320 x 224 that fits the container, the backing store is set to exactly that, and the CSS width is the backing store divided by `devicePixelRatio` so the two agree to a fraction of a device pixel. The stylesheet must therefore never give `#game-canvas` a `width` or an `aspect-ratio` — a `width: 100%` box inside the 720 px container is what put a 960-wide framebuffer into a 716 px box, a 0.746x nearest-neighbour downscale that dropped a quarter of the framebuffer's rows and columns. This cabinet is also the one place `setupHiDpiCanvas` is deliberately not used, for the reason written at `fitCanvas`: its contract is that CSS owns the box and it clamps the ratio at 3, and here neither holds. `font.ts` ships a 5x7 bitmap font drawn with batched `fillRect` runs — the cabinet never calls `fillText`, which would be the one anti-aliased thing on screen — and covers the accented capitals Spanish and Catalan need, with `tests/games/football-render.test.ts` asserting that every `fun.football.*` string in all three locales has a glyph and that no source file carries a hex literal off the Mega Drive's 3-bit ladder. The DOM-free modules are `pitch.ts` (geometry, formation anchors, the pure `cameraFor`), `teams.ts`, `match.ts` (ball with a real height axis, possession, the three stoppages, the compressed 0'-to-90' clock), `keeper.ts` (a **probabilistic** keeper — being within reach is a save *roll*, never a certainty; he **stands on the angle** rather than on the ball, `narrowAngleX` putting him on the bisector of the angle the mouth subtends from it, which is what makes a wide position a narrow target rather than a free far post; his **gap is how near the ball passed him** (`approachGap`), not the difference of two lateral coordinates, because his reach is a radius and a ball dragged across goal travels through the space he is standing in; his **reach is what he can get to in the time he has** (`REACH_BODY` growing to `REACH_BASE` over `REACT_TIME`); and he gets **exactly one roll per ball** (`KeeperRuntime.contested`), which is what finally consulted him about a shot struck from *inside* his standing line), `ai.ts`, `setpieces.ts`, `shootout.ts` and `tournament.ts` (two groups of four, 2-1-0, top two through, semi then final, plus `runScore` as the single place the run's number is computed). **The roster is real national sides** (2026-08-15, at the owner's request): the twelve that enter a run are countries that played the 1990 tournament, `code` carrying the standard three-letter abbreviation and `name` the country, all plain unaccented ASCII so the existing glyph-coverage test passes untouched and the names read the same in all three locales. Every score moved out of its `game.ts` into a **`src/games/<game>/music.ts` module exporting a `GameAudioOptions`**, which is now the required channel for a cabinet's music — a score inline in `game.ts` is the thing this round removed, since the note data is larger than the game code that plays it and is the part worth reading on its own. CALCIO '90 was not in that round (it was unlisted at the time and its score was still inline in its `game.ts`); it adopted the channel on 2026-08-15, which is when the glob's promise below was first collected on, and its arrival is what proved the equal-length invariant catches a real defect rather than a stylistic one. Loop lengths went from 8–24 beats to 32 (Snake, Cascade, Tank Duel) or 48 (Microcity, Critter Rescue, Line Hold, Pixel Park, Syndicate), every one at least double what it was, and the ratio is pinned per cabinet in `tests/games/music.test.ts` alongside the round's load-bearing invariant: **every voice in a cabinet loops at the same number of beats**. The voices advance on independent cursors, so unequal lengths do not drift and recover, they slide permanently — a 25-beat lead over a 24-beat bass puts the tune's downbeat on a different bass note every time round. Three engine additions serve the arrangements. `Note.gain` is an **attenuation-only** per-note level (clamped 0.05–1, and only downwards on purpose, so a line is shaped by ducking its weak beats rather than boosting its strong ones and every voice's ceiling stays at the track volume the mix was balanced at); before it, every note in a voice fired at one level, which is most of what made a decent line read as a machine playing it. `src/games/engine/pitch.ts` gives `pitch(name)`/`p(name)` in scientific pitch notation and **throws on an unparseable name** rather than falling back — the scores previously carried raw Hz with the note name in a trailing comment, which is fine at a dozen notes and a liability at several hundred, since the comment was the only record of what was meant. Be precise about where that throw is caught, because the cost of missing it is high: the scores are module-level constants, so a bad name throws at import time inside the cabinet's client bundle and the visitor gets a **dead page**, not one wrong note. The build does not catch it (it bundles these modules without ever executing them) and `typecheck` cannot see inside a string literal. `tests/games/music.test.ts` is the only gate, which is why it discovers the modules with `import.meta.glob` rather than importing a hand-written list: merely pulling every `music.ts` into that suite is what converts a typo into a test failure, and a new cabinet is covered without anyone remembering to enrol it. Three further engine rules came out of the round's review, all from the same root — the scheduler was written when every note was short, and sustained pad voices broke each assumption. `scheduleAhead` commits a whole note's real-time duration at the tempo in force when it schedules it, so **`setTempo` rescales every pending cursor** by the tempo ratio; without that, a long-note voice stays on old-tempo timing for its whole in-flight note while short-note voices re-time within the 0.1s lookahead, and each change adds a slip that never comes back (measured at roughly a beat and a half across Cascade's thirteen level-ups, heard as the previous bar's chord still sounding under the current one). **`stop()` ducks the music master**, because dropping the scheduler only stops *new* notes and a 4-beat voice would otherwise drone for two seconds over the game-over sting; `start()` lifts it again with a ramp rather than a `.value` write, since a scheduled ramp outranks a later assignment. And **un-muting resets every cursor**, because muted scheduling advances the cursors without creating oscillators, so a voice that stepped over a long note would return up to a full note late and the mix would audibly reassemble itself in stages. Cascade's `BASE_TEMPO` moved into its music module (it is the score's own tempo; `TEMPO_PER_LEVEL`/`MAX_TEMPO` stay in `game.ts` as ramp policy). Each cabinet keeps the identity Round 11 gave it — Snake is still the deliberately minimal one at two voices with no pad and no echo (pinned by a test), Pixel Park is still a 3/4 carousel waltz, Syndicate still Blade-Runner dread — but Cascade, Tank Duel and Critter Rescue each gained a third voice, and the parked cabinets (Pixel Park, Syndicate) were rescored with the rest so a revival stays a page rename and nothing else.

Scoring conventions across the cabinets: there is **one board**, the global one every visitor shares, served by a Vercel Function at `api/scores.ts` backed by Vercel Blob (client seam `src/games/engine/globalScores.ts`, submission wired into `scoreboard.ts`'s `commit()`; the rejected alternatives and the Cloudflare-to-Vercel reversal behind this choice are in `docs/adr/002-global-arcade-high-scores.md`, whose "Corrections from production" section records what running the write path for real disproved: `put` has no conditional *create*, so an absent read is never taken at face value; it also records that the CDN does cache the read on plain `max-age`, measured against the deployed endpoint after a review claimed otherwise, so `s-maxage` is belt-and-braces rather than load-bearing). What `highscores.ts` still keeps on the device is only the last-used initials and a **personal best number per game** (`loadBest`/`saveBest`, key `arcade-best-<gameId>`, migrating once from the retired `arcade-hs-*` tables and then from the pre-table single-number keys; a cabinet whose scoring scale changes gets a version suffix through `BEST_KEY_VERSION` instead — today only `tanks`, at `-v2`, whose old key held a 100–400 match margin that the ledger score outgrew by an order of magnitude, and a rescaled game reads its versioned key alone since every older source predates the change); that number is what `best()`, the HUD readouts, the record toast, and the arcade floor's attract screens read. Four rules here are load-bearing and easy to undo by accident, so do not re-gate them. **Every finished run with a score above zero is submitted** — `qualifies()` decides only whether the player is interrupted for initials, never whether the run reaches the board, because gating the submission on a private table is exactly the bug that left eight of the nine live boards holding a single entry each (regression pinned in `tests/games/scoreboard-dom.test.ts`). The board is **refetched at panel init and again at every run end**, since a player has no refresh button and a once-only load froze the shared board for a whole session. And both a fetch's reply and a submission's own reply are ordered by the single `worldGen` generation that only a submission bumps, so an overtaken or out-of-order answer stands down instead of putting an older board back on screen. Finally, **a submission that does not land says so** in the panel note (`fun.arcade.scoreNotSaved`), because with no device table behind it a failed write loses the run outright; the notice is gated on `canSubmit()` so local dev and previews, which read the board but never write to it, stay quiet rather than crying wolf. `commit()` records the finished run through the run record's `bank()` rather than writing `saveBest` behind its back (so `best()` and storage cannot disagree mid-session), and fires `onSave` once per committed run whatever became of it, with rank 0 when it did not chart or did not land. Server-side, `top` is the **persisted all-time top ten**, merged per write by `mergeTop` rather than re-derived from a rolling history (which silently expired records once a board passed the history cap), and one pruned `recent` array carries replay dedupe plus both rate limits. Beyond that: games whose runs can be long (Microcity, Pixel Park, Syndicate, Line Hold, Cascade, Tank Duel) bank the run's best as it grows — `bank(score)` stashes automatically — so a closed tab never loses a record; every point gain is announced on screen the moment it lands (canvas floaters/score popups via `createEffects`); the number a finished run submits is shown to the player rather than computed silently (e.g. Tank Duel's match score, Critter Rescue's bonus breakdown); and beating the personal best mid-run earns a one-time toast driven by `bank()`'s `newRecord` flag; Critter Rescue is also long-run but banks on level-clear only, and never calls `beginRun()`, which leaves the celebration unarmed so it fires no mid-run record toast. `bank()` is the **only** write path to the persisted best: the `Scoreboard` interface deliberately exposes no second verb for it, so the number in memory and the one on disk cannot drift apart.

Tank Duel was the cabinet that broke every one of those conventions at once, and was rebuilt to them on 2026-08-12. A single `playerWonMatch` boolean used to decide three separate things — whether the score was visible, whether the panel opened, and whether the run was offered — so a player who did not beat the CPU saw no number at any stage of a match; and the number itself, `physics.ts`'s retired `matchScore` (round margin × 100 + surviving armour), only existed at match end and was negative for most of a match's life. The rules now live in `src/games/tanks/scoring.ts` and are pure and unit-tested (`tests/games/tanks.test.ts`): `createScoreLedger()` pays **1 point per hp of damage landed on the opponent** as it lands, **25 for detonating a shell on the enemy hull**, **250 for taking a round**, and folds **surviving armour in once at match end**. Self-damage and fall damage (a drop has no shooter) pay nothing, and **nothing is ever subtracted** — the ledger's private `add` drops any non-positive award rather than banking it, because a negative running total was the original bug in miniature. Both modes score identically and both call `beginRun()`; the awards fire gold `+NN` floaters through the shared `createEffects` beside the red damage popups, and drive SCORE and BEST readouts plus the record toast through the shared `createToaster`. Only **submission** differs, through the pure `submitsToBoard(mode)`, which is `mode === 'cpu'` and nothing else. Two-player never reaches the world board and never banks against the personal best that feeds the floor's attract screens, because one person driving both tanks can farm any total they like; a 2P match ends instead on a local-only overlay showing both totals side by side. The gate is deliberately *not* also conditioned on winning — a lost match that earned 900 points is a finished run worth 900, and `qualifies()` decides only whether to interrupt for initials. The bespoke `tanks-victories` counter is retired with the old scoring (its `LEGACY_KEYS` exclusion note in `highscores.ts` still stands); its header slot now carries SCORE, beside a BEST that swaps out for the second player's score in two-player.

What a run is worth, and when it is allowed to end, was corrected across four cabinets in August 2026. Line Hold scores waves **held**, not waves survived (`wavesHeld × WAVE_BASE + killScore`): a wave whose every marcher walked into the keep still advances the run and still pays interest, but scores nothing, which is what closed the idle-tab exploit that banked 200 points for pressing Start and walking away. The leak count lives on `Economy` behind `leak()`, the one door every marcher reaching the keep goes through, and `clearWave(eco)` reads and resets it and returns `{ held, interest }`, so the game loop and the headless harness cannot disagree about which waves were held; `wavesCleared` stays as the run's progress counter. Interest on a leaked wave was measured rather than assumed and deliberately kept: withholding it never improved a run, cost a sub-optimal one up to a full wave, and the exploit scores zero either way. (`docs/plans/2026-07-12-next-arcade-game-design.md` still carries the old "waves cleared × base" formula; it is a historical plan and is left as written.) Cascade's no-full-row guard now lives inside `resolveClears` rather than at its call sites, so no later caller can reintroduce the phantom clear where the top-out settle collapsed every floating cell and scored whatever rows the landslide happened to finish. Microcity has a terminal state other than failure: a **Retire** control, in its own group beside the speed buttons, ends a solvent run through the same `gameOver` path, so a thriving city can reach the board at last, and it is guarded by an `alertdialog` confirmation (Cancel takes focus, Escape dismisses, Tab is trapped, the handler is bound on `document` and torn down through the repo's `astro:before-swap` idiom) because a single stray click next to fast-forward should not end a city built over many minutes. A `confirm` phase holds the run still while the prompt is open, which every existing `phase !== 'play'` guard picks up for free.

Critter Rescue fires **no automatic ending** on a stalled field, and its merged commit message (`e8bca37d`, "every level runs under a clock so a stalled one always ends") describes an approach that was abandoned before it shipped: read `src/games/lemmings/stall.ts` rather than the subject line. Three rounds of automatic endings each took a run off a player who was still playing, so the fallback clock and the standstill endings are gone, and every ending that is not the level resolving itself is now the player's own, through one of two doors. The Nuke button concedes a level the crowd can no longer finish. The second door arrived on 2026-08-15 (#283): an **End Run** button (`endRunBtn` and the `runEnded` flag in `src/games/lemmings/game.ts`), offered on a mid-run clear and only there, because that is the one result screen that leaves the run open, a failed quota and the final victory both reaching the board on their own. It is Microcity's Retire under another name, for the same reason, and it is what actually banks a multi-level run: it calls `board.show(runScore)`, where the `board.hide()` a mid-run clear otherwise takes commits nothing because nothing was ever pending, and it retitles the continue button to Play Again so the screen cannot offer to carry a finished run into another level. Carrying on to the next level still submits nothing, which is deliberate and pinned alongside the rest in the `describe('ending a run from a mid-run clear (#261)')` block of `tests/games/lemmings-dom.test.ts`. The pure `levelEnding`, shared by the game loop and the playthrough harness so neither can certify an ending the other would not, resolves a level only when the crowd settles or an authored `timeLimit` runs out; the standstill detector survives purely as an on-screen hint (`STUCK_TICKS`, 480) naming the Nuke button, which is labelled and documented in all three locales. The guarantee is therefore **"no level is ever unescapable"**, not "no level runs forever": on a level whose crowd can no longer reach the exit `levelEnding` answers null forever and the way out is the player's, proved by playing all 25 levels through that escape hatch. Billing follows the same line: every ending the level itself reaches is billed on real elapsed ticks (an authored clock is billed for the whole limit, or it pays a speed bonus for time the countdown genuinely consumed), and only conceding freezes the bill at the tick the field last moved, so the wait before the hint appears is not charged back to the player.

The convention that batch left behind, and the most reusable thing in it: **a cabinet needs at least one test that plays it to completion and asserts a player-visible outcome, not a mechanical invariant.** Four review rounds ran over the six PRs, locally through a review workflow rather than as GitHub review comments, so the inline-comment counts on those PRs measure nothing about what the rounds found. Three findings are worth keeping because each is checkable against the repo. Some assertions could not go red at all: Critter Rescue's "every level resolves" proof resolved the harness on `levelTimeLimit` (at most 9000) while its runaway guard sat at 12000, so `endedAt` was never null and every assertion passed unconditionally, and Snake's last-move check ran only on steps where the rung advanced, where with a grace in front of every claim no wall sets, so it compared two identical wall sets. (The harness now keeps `maxTicks` independent of anything under test, and ten levels duly report null.) Microcity's DOM suite passed only by scheduling luck, on the `performance.now()` clock trap described under Testing. And one test pinned broken arithmetic as a feature: an interim Syndicate test, `walks the asset onto the pad rather than parking it behind the squad`, asserted that a trailing asset settles *outside* the extraction radius, which is precisely the sum that made mission 10 unwinnable, on a leg nothing had ever played (before PR #277 the escort win was only ever probed by handing `missionStatus` a boolean). It is now two tests that state the relation instead, `keeps the escort gap tighter than the pad an agent has to stand on` and `delivers the asset by trailing an agent that stands on the pad`. Issue #260 tracks carrying this across the remaining cabinets.

### Layouts and Components

`src/layouts/Layout.astro` is the base layout with navigation, language switcher, and footer. `src/layouts/ArticleLayout.astro` handles article pages. Components in `src/components/` are shared across locales.

Top-level nav is deliberately four items — Home, About, Projects, Writing (owner-approved simplification, 2026-08). `src/pages/[lang]/connect.astro` was removed: its grouped link lists (the `LinkCard`-rendered `read`/`connect` groups from `src/data/links.ts`, including the RSS `feedLink`) now live inside `about.astro` under an `id="connect"` section, so every CTA that used to point at `/connect` (the Hero button, the footer link, the article "discuss" link) now targets `/about#connect` directly. `astro.config.mjs`'s `redirects` sends the three old `/{lang}/connect` paths to `/{lang}/about#connect` for anyone with a stale bookmark or inbound link. `/health` stays fully live and linked (a "Project health" link sits next to the `PortfolioHealthBadge` on `projects.astro`) but is no longer in the nav bar.

### Testing & CI

Vitest tests live under `tests/` (unit tests for i18n and reading-time, the arcade game-logic suites under `tests/games/`, plus `tests/build/output.test.ts` which reads files from `./dist` and is skipped unless a build has been produced). Vitest runs in the node environment by default; jsdom is installed and opted into per file (`/** @vitest-environment jsdom */`), which is how `tests/games/scoreboard-dom.test.ts` covers `scoreboard.ts`'s DOM wiring — other DOM-wired changes are still verified in a browser against `npm run dev`. The link checker in `scripts/check-links.js` walks built HTML in `./dist/` and verifies internal hrefs resolve to real files. CI (`.github/workflows/ci.yml`) runs lint, typecheck, build, tests, and link check on pushes to `main`/`develop` and PRs to `main`.

### Deployment

The deploy workflow (`.github/workflows/gh-pages.yml`) runs after a successful CI on `main` (and on a six-hourly cron) to build and publish to GitHub Pages. Output goes to `./dist`. The Vercel deployment (configured by `vercel.json`) mirrors the site and is the production host for the global-scores Function at `api/scores.ts` (see ADR 002).
